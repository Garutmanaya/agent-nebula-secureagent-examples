# 04. A2A multi-skill over HTTPS

## Purpose

Make verified TLS the next baseline capability while retaining the multi-skill behavior established in Example 02. The server exposes `hello`, `echo`, and `add` over an HTTPS JSON-RPC A2A interface. The client trusts the local example CA generated by `make init example-04`; certificate verification is never disabled.

This example intentionally isolates HTTPS from Example 03's multi-binding test. gRPC transport security is a separate concern from HTTPS and should not be implied by an example whose feature under test is HTTPS.

## Test coverage

The client verifies the Agent Card advertises HTTPS and invokes every skill through the TLS-protected interface. It fails non-zero for certificate/trust failures, incomplete Agent Card configuration, dispatch errors, or unexpected responses.

## Initialize and run

```bash
make init example-04
make run example-04 server
```

In another terminal:

```bash
make run example-04 client
```

`make init example-04` creates a short-lived local CA and a server certificate valid for `localhost` and `127.0.0.1`. The client configuration references `trust/local-ca.crt`, so the connection performs normal peer verification. These certificates are development-only.

## Cleanup

```bash
make clean example-04
```
